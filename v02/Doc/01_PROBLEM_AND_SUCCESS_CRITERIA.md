# Problem Definition and Success Criteria

## 1. Real problem

Student grievances are often handled through disconnected channels such as email, forms, messaging applications, physical offices, and department-specific processes. This creates:

- repeated complaints about the same issue;
- manual forwarding and incorrect routing;
- no consistent urgency model;
- poor visibility for students;
- departments working from different queues;
- weak SLA accountability;
- difficulty measuring institutional problem patterns;
- loss of historical context when cases are closed.

The platform solves the **coordination and intelligence problem around grievances**, not merely the submission problem.

## 2. Problem statement

Design a centralized, AI-assisted grievance management platform that can ingest a complaint, understand its category and urgency, identify duplicate or related complaints, route it to the correct authority, track SLA compliance, support departmental resolution, and maintain an auditable history from submission to closure.

## 3. Primary outcomes

| Outcome | What success looks like |
|---|---|
| Correct routing | Complaints reach the right department with minimal manual forwarding |
| Faster prioritization | High-impact cases rise above routine cases |
| Duplicate reduction | Related complaints are grouped instead of processed repeatedly |
| Transparency | Students can see status and meaningful updates |
| Accountability | Every active complaint has an owner and SLA |
| Institutional learning | Aggregated complaints reveal recurring systemic issues |
| Safe automation | AI decisions are explainable and overrideable |

## 4. Measurable KPIs

Track these during the pilot:

- routing accuracy;
- duplicate detection precision/recall;
- median first-response time;
- median resolution time;
- percentage resolved within SLA;
- percentage requiring manual rerouting;
- percentage of AI decisions overridden;
- student validation rate;
- reopen rate;
- backlog by department;
- recurring issue clusters;
- average number of duplicate tickets consolidated per cluster.

Do not invent benchmark numbers in the pitch. State that baseline and target values will be measured during pilot deployment.

## 5. Sustainability

The system becomes more valuable over time because:

1. historical complaints improve duplicate and trend analysis;
2. department-level SLA data reveals bottlenecks;
3. recurring clusters identify systemic problems;
4. human corrections can become labeled data for future model improvement;
5. configuration allows new departments and policies without rewriting the core system.
